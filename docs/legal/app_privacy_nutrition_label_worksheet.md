# FitConnect 앱 개인정보 표시 워크시트

기준일: 2026-06-04
대상: Apple App Privacy Nutrition Label, Google Play Data safety 입력 준비
문서 상태: 초안. 실제 SDK, 권한, API 전송, 스토리지, 로그, 광고/분석 도구 도입 여부와 대조해야 합니다.

## 1. 기준 요약

- Apple은 앱과 통합된 제3자 코드가 수집하는 데이터 유형, 사용자와 연결되는지, 추적에 사용되는지를 App Store Connect에 입력하도록 요구합니다.
- Google Play는 앱이 수집 또는 공유하는 사용자 데이터, 전송 중 암호화, 삭제 요청 메커니즘, 필수/선택 수집 여부를 Data safety form에 입력하도록 요구합니다.
- 온디바이스에서만 처리되고 기기 밖으로 전송되지 않는 데이터는 표시 방식이 달라질 수 있습니다. FitConnect는 현재 식단 대화와 추천 기록을 서버에 저장하므로 해당 항목은 수집으로 보는 것이 보수적입니다.

## 2. 현재 데이터 흐름 가정

| 영역 | 현재/계획 |
| --- | --- |
| 로그인 | 이메일/비밀번호, Kakao OAuth, Supabase Auth |
| 서버 저장 | Supabase/PostgreSQL에 프로필, 예약, 식단 로그, 채팅, 추천 기록 저장 |
| 이미지 분석 | API가 음식 이미지를 받아 분석. 원본 장기 저장은 미확정이며 저장하지 않는 구조 권장 |
| AI | Ollama 로컬 LLM 기준. 외부 LLM 전송 도입 시 즉시 업데이트 필요 |
| 분석/광고 | 제3자 광고 SDK 없음. 의류 추천 클릭/구매 전환 추적 계획 |
| 결제 | MVP 이후 도입 예정. 결제대행사 도입 시 금융/구매 데이터 추가 |
| 삭제 | 이메일/고객지원과 앱 내 삭제 기능 계획. Google Play 삭제 메커니즘 표시 전 구현 필요 |

Apple 제출 전 확인:

- [ ] `expo-image-picker` 권한 문구와 실제 이미지 업로드 흐름 확인
- [ ] Apple Health/HealthKit 연동 여부 확인. 현재 미사용
- [ ] 광고 추적, 데이터 브로커 공유, 제3자 타겟 광고가 없는지 확인
- [ ] crash/analytics SDK가 수집하는 데이터와 개인정보 manifest 확인
- [ ] 결제 기능 도입 시 purchase history 업데이트

## 6. 공개 라벨 초안 요약

보수적 공개 방향:

- 수집함: 연락처 정보, 건강 및 피트니스, 사용자 콘텐츠, 식별자, 사용 데이터
- 향후 수집 가능: 구매 내역, 진단 데이터, 알림 토큰
- 추적 목적 사용: 없음으로 계획. 광고 SDK, 데이터 브로커, 제3자 타겟 광고 도입 시 변경
- 사용자와 연결: 계정 기반 기능 대부분은 연결됨
- 삭제 요청: 제공 예정. 출시 전 실제 경로 구현 필요
- 전송 중 암호화: 운영 HTTPS 적용 후 표시
